identify CD-system functions. Original private C names are not claimed.

`provenance.json` records comparisons against the entire function ranges in
Psy-Q 4.3 signature JSON from `psx-ruby/.tools/psyq-sigs/430/`, including source
hashes, SDK offsets and relocation wildcard counts. Every known signature byte
matches. The regression test independently links each C function at its retail
address and checks every byte through fixed SHA-256 hashes, without wildcarding
relocations. No retail image or proprietary compiler executable is needed by
that test.

## Recovered source and records

- `_dirFailAuto` advances the per-port failure counter, updates retry state,
  invokes the configured callback when appropriate, and invalidates the output
  for a response other than 0xF3. It needs no pins or barriers.
- The PADCMD reader handles 16-bit entries, five-byte capability records, and
  length/pointer records followed by aligned payload storage. `card_obj.h` now
  defines the latter two layouts, with size and offset assertions. Capability
  bytes retain neutral names because their protocol meanings are not recovered.
- The DSSYS_2 queue flush collects callbacks by consecutive command identifier,
  notifies the result queue, clears all eight pending entries, resets its
  indices, then invokes the saved callbacks. Its eight-byte callback record and
  twelve-byte index block are shared in `psyq_ds_queue.h`, with layout checks.
- The DSSYS_1 sync handler updates command status, mode and position, then
  dispatches the registered sync callback when the CD system is enabled. It
  reuses the existing CD state structures; their provisional field names are
  not proof of protocol semantics. In particular the existing `reserved34`
  field receives 1200 on the read-command path.

Legacy link symbols remain intact. The functions reside under `psyq/libpad`
and `psyq/libds`, and the switch table belongs to its C unit.

## Validation and debt

- Native, unmodified GCC 2.7.2 and the existing GNU assembler route.
- `make -j8 check`: the entire main.exe matches retail SHA-1
  `452fb033f2eaa4b18aa20a5bca60b8125af3a37b`.
- `make ci`: 319 tests, including all four complete linked text hashes and the
  complete switch table hash.
- `make report` passes the semantic-progress audit: 2,400,916 bytes and
  10,517 functions credited. `main-psyq` reports 221/278 functions and
  84.46% code after adding the four SDK identifications to that category.
- No toolchain changes or instruction-bearing inline ASM.
- Remaining matching debt: 10 pins, 15 empty barriers and 11 gotos, recorded in
  `tools/crutch_debt_baseline.json`. Two successive removal passes verified
  which individual constraints could be removed without changing linked bytes.
- All four new units classify as semantic C. The existing 28 constrained units
  and legacy `asm_bodies: 71` counter are unchanged. That legacy regex count can
  miscount symbol aliases and is not a verified count of CPU instruction blocks.

Byte equality and layout checks validate the emitted program; this change does
not claim independent execution of hardware behavior on a console.
